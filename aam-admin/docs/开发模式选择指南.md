# AAM Admin 开发模式选择指南

**创建日期**: 2025-01-14  
**目的**: 帮助选择最适合的开发模式，避免资源浪费和混淆

---

## ⚠️ 混合模式的问题分析

### 潜在问题

#### 1. 资源占用（Loading）

**混合模式**:
- Docker 容器：数据库服务（PostgreSQL）
- 本地进程：后端服务（Python + Uvicorn）
- 本地进程：前端服务（Node.js + Vite）

**资源占用**:
- Docker 容器：~100-200MB 内存
- 后端进程：~50-100MB 内存
- 前端进程：~50-100MB 内存
- **总计**: ~200-400MB 内存

**Docker 模式**:
- Docker 容器：数据库服务（PostgreSQL）
- Docker 容器：后端服务（Python + Uvicorn）
- 本地进程：前端服务（Node.js + Vite，可选）

**资源占用**:
- Docker 容器：~200-300MB 内存
- 前端进程：~50-100MB 内存（如果本地运行）
- **总计**: ~250-400MB 内存

**结论**: 资源占用差异不大，但 Docker 模式更统一。

---

#### 2. 环境混淆

**混合模式的问题**:
- ❌ 需要同时管理 Docker 和本地环境
- ❌ 依赖版本可能不一致
- ❌ 调试时需要切换上下文
- ❌ 端口管理分散（Docker + 本地）

**Docker 模式的优势**:
- ✅ 环境完全统一
- ✅ 依赖自动管理
- ✅ 调试上下文一致
- ✅ 端口统一管理

---

## 🎯 推荐方案

### 方案一：纯 Docker 模式（推荐用于生产环境一致性）

**配置**:
- 数据库：Docker
- 后端：Docker
- 前端：本地（Vite 热重载更快）

**启动方式**:
```bash
# 启动数据库和后端（Docker）
docker-compose -f docker-compose.dev.yml up -d

# 启动前端（本地）
./scripts/start-service.sh frontend
```

**优点**:
- ✅ 环境一致性高
- ✅ 资源管理统一
- ✅ 更接近生产环境
- ✅ 依赖自动管理

**缺点**:
- ⚠️ 启动稍慢
- ⚠️ 调试需要进入容器

---

### 方案二：完全本地模式（推荐用于快速开发）

**配置**:
- 数据库：Docker（数据持久化需要）
- 后端：本地
- 前端：本地

**启动方式**:
```bash
# 启动所有服务（混合模式）
./scripts/start-service.sh all
```

**优点**:
- ✅ 启动快速
- ✅ 调试方便
- ✅ 热重载响应快

**缺点**:
- ⚠️ 需要本地安装 Python/Node.js
- ⚠️ 环境可能不一致

---

### 方案三：完全 Docker 模式（推荐用于环境测试）

**配置**:
- 数据库：Docker
- 后端：Docker
- 前端：Docker（可选）

**启动方式**:
```bash
# 使用 Docker Compose 启动
docker-compose -f docker-compose.dev.yml up -d
```

**优点**:
- ✅ 环境完全一致
- ✅ 资源管理统一
- ✅ 无需本地安装依赖

**缺点**:
- ⚠️ 启动较慢
- ⚠️ 前端热重载可能较慢

---

## 💡 最佳实践建议

### 日常开发

**推荐**: 混合模式（当前默认）
```bash
./scripts/start-service.sh all
```

**理由**:
- 启动快速
- 调试方便
- 资源占用适中

---

### 环境测试

**推荐**: 纯 Docker 模式
```bash
./scripts/start-service.sh all --docker
```

**理由**:
- 环境一致性
- 更接近生产环境
- 避免环境混淆

---

**推荐**: 完全 Docker 模式

docker-compose -f docker-compose.prod.yml up -d

**理由**:
- 环境完全一致
- 资源管理统一
- 易于扩展和维护

## 🚨 注意事项

### 1. 端口冲突

**检查端口占用**:
```bash
# 检查端口占用
lsof -i :8003  # 后端
lsof -i :3000  # 前端
lsof -i :5433  # 数据库
```

### 2. 资源清理

**清理未使用的资源**:
```bash
# 停止所有服务
./scripts/stop-service.sh all

# 清理 Docker 资源
docker-compose -f docker-compose.dev.yml down
docker system prune -f  # 清理未使用的 Docker 资源
```

### 3. 环境隔离

**使用虚拟环境**:
- 后端：Python 虚拟环境（`backend/venv`）
- 前端：Node.js 项目依赖（`frontend/node_modules`）

---

## 📝 总结

**混合模式的影响**:
- ⚠️ 资源占用：中等（~200-400MB）
- ⚠️ 环境混淆：可能（需要同时管理 Docker 和本地）
- ⚠️ 端口管理：分散（Docker + 本地）

**推荐方案**:
1. **日常开发**: 混合模式（快速、方便）
2. **环境测试**: 纯 Docker 模式（一致、统一）
3. **生产部署**: 完全 Docker 模式（一致、可扩展）

**优化方向**:
- 提供模式切换选项
- 添加资源监控
- 统一端口管理
