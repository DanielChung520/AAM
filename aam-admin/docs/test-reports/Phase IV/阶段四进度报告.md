# 自动记录所有管理操作
audit_service.log_operation(
    user_id=user.id,
    action=AuditAction.UPDATE,
    resource_type="service",
    resource_id="aam-service",
    description="POST /api/v1/admin/services/aam-service/start",
    ip_address="192.168.1.100",
    user_agent="Mozilla/5.0...",
    request_data={"action": "start"},
    status="success",
    before_state={"status": "stopped"},
    after_state={"status": "running"},
)

- 排除不需要审计的端点（如登录、审计日志查询本身）

**操作信息提取**:
- 从请求中提取方法、路径、IP地址、User-Agent
- 从请求体中提取请求数据（JSON 格式）
- 从路径中提取资源 ID（支持数字 ID、UUID、字符串 ID）

**状态对比**:
- 对于更新操作，记录操作前状态
- 操作成功后，记录操作后状态
- 状态存储在 request_data 的 before_state 和 after_state 字段中

   - 建议：后续根据资源类型实现具体的状态获取逻辑

4. **数据库模型扩展**
   - 当前使用 `request_data` JSON 字段存储操作前后状态
   - 建议：后续可添加专门的 `before_state` 和 `after_state` 字段（需要数据库迁移）

1. **审计日志记录性能**
   - 审计中间件在请求处理过程中同步记录日志
   - 建议：后续可考虑使用异步任务队列（如 Celery）异步记录日志

2. **大量日志查询性能**

   - 建议：后续可考虑使用数据库分区或归档机制

3. **趋势分析性能**
   - 当前使用原生 SQL 进行分组统计
   - 建议：后续可考虑使用数据库视图或物化视图优化查询性能
