**创建日期**: 2025-01-14  
**状态**: ✅ 支持两种开发模式

---

## 📋 开发模式总览

AAM Admin 支持两种开发模式，可以根据需要选择：

### 1. 本地开发模式（默认，推荐日常开发）

**配置**:
- 数据库：Docker 容器
- 后端：本地 Python 虚拟环境
- 前端：本地 Node.js

**启动方式**:
```bash
# 启动所有服务（本地模式）
./scripts/start-service.sh all

# 仅启动后端（本地模式）
./scripts/start-service.sh backend

# 仅启动前端
./scripts/start-service.sh frontend
```

**优点**:
- ⚡ 启动快速
- 🔧 调试方便（可以直接调试 Python 代码）
- 🔥 热重载响应快
- 📝 日志直接输出到终端

**缺点**:
- ⚠️ 需要本地安装 Python 和 Node.js
- ⚠️ 环境配置可能不一致

---

### 2. Docker 开发模式（推荐环境测试）

**配置**:
- 数据库：Docker 容器
- 后端：Docker 容器（代码卷挂载，支持热重载）
- 前端：本地 Node.js（前端通常使用本地模式）

**启动方式**:
```bash
# 启动所有服务（Docker 模式）
./scripts/start-service.sh all --docker

# 或使用 docker 命令
./scripts/start-service.sh docker

# 仅启动后端（Docker 模式）
./scripts/start-service.sh backend --docker

# 使用 Docker Compose 直接启动
docker-compose -f docker-compose.dev.yml up -d
```

**优点**:
- ✅ 环境完全一致
- ✅ 无需本地安装 Python
- ✅ 更接近生产环境
- ✅ 支持代码热重载（卷挂载）

**缺点**:
- 🐢 启动稍慢
- ⚠️ 调试需要进入容器

---

## 🔄 混合模式（当前推荐）

**配置**:
- 数据库：Docker（确保数据持久化）
- 后端：本地开发（快速调试）
- 前端：本地开发（快速热重载）

**使用场景**:
- ✅ 日常开发（推荐）
- ✅ 快速迭代
- ✅ 调试和测试

**优点**:
- 环境一致性
- 更接近生产环境

### 生产部署（使用 Docker 模式）

```bash
# 使用 Docker Compose 启动
docker-compose -f docker-compose.dev.yml up -d
```

## 🔧 Docker 开发环境配置

### 已配置的服务

#### 1. Admin Database
- 容器名: `admin-db-dev`
- 端口: `5433:5432`
- 数据卷: `admin_db_data_dev`

#### 2. Admin Backend
- 容器名: `admin-backend-dev`
- 端口: `8003:8003`
- 代码卷挂载: `./backend/src:/app/src`（支持热重载）
- 测试卷挂载: `./backend/tests:/app/tests`
- 启动命令: `uvicorn src.main:app --host 0.0.0.0 --port 8003 --reload`

### Docker Compose 命令

```bash
# 启动所有服务
docker-compose -f docker-compose.dev.yml up -d

# 查看服务状态
docker-compose -f docker-compose.dev.yml ps

# 查看日志
docker-compose -f docker-compose.dev.yml logs -f admin-backend

# 停止服务
docker-compose -f docker-compose.dev.yml down

# 重启服务
docker-compose -f docker-compose.dev.yml restart admin-backend
```
